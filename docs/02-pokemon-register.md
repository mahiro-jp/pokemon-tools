# ポケモンツール：ポケモン登録画面

共通レイアウトや画面遷移は[ホーム画面の仕様書](./01-home.md)、色・文字・余白・部品・レスポンシブ対応は[スタイルガイド](./00-style-guide.md)を参照する。この仕様書ではポケモン登録画面固有の要件を定める。

## 1. 機能概要

- 対戦用ポケモンの基本情報、能力ポイント、技、ダメージ計算メモ、備考を登録・検索・編集・削除する。
- 登録データはブラウザーの `localStorage` に保存し、再読み込み後も利用できるようにする。
- 画面は既存の単一ページ構成に追加し、URLハッシュ `#pokemon` で表示する。共通ヘッダー、ナビゲーション、フッターは維持する。
- 実装はHTML・CSS・Vanilla JavaScriptで行う。外部フレームワーク、ライブラリ、サーバーサイド処理は使用しない。

## 2. 画面構成と操作

### 2.1 登録データの呼び出しと新規作成

- **登録済みポケモンを検索する**
  - 登録済みデータの一覧はドロワーで表示する。
  - ポケモン名、タイプで絞り込めるようにする。
  - 一覧から選ぶと、そのデータをフォームに読み込み、編集状態にする。
  - 登録がない場合は空状態と、登録を始める方法を表示する。
- **新規作成**
  - フォームを初期状態に戻し、新規登録状態にする。
  - 編集中の未保存内容がある場合は、破棄することが分かる確認を行う。

### 2.2 基本情報

- **ポケモン**：図鑑データから検索・選択する。選択後、画像、タイプ、種族値（HP・こうげき・ぼうぎょ・とくこう・とくぼう・すばやさ）を表示する。
- **特性**：現在表示中のフォームが持つ特性のみを選択肢に表示する。
- **性格**：全21種類から選ぶ。上昇・下降補正が分かる表記（例：`いじっぱり（こうげき↑ とくこう↓）`）にする。無補正の性格は「まじめ」のみとし、初期値も「まじめ」とする。
- **持ち物**：持ち物マスターデータから検索・選択する。
- **新規登録中のポケモン変更時**：能力ポイントをすべて `0` に戻す。選択したポケモンが持たない特性や覚えない技は選択解除し、選択肢と表示を更新する。登録済みデータを呼び出したときは、保存済みの能力ポイントや選択内容を維持する。
- **メガシンカ表示**：選択中のポケモンがメガシンカ可能で、持ち物に共通の「メガストーン」を選択している場合、画面上のポケモン表示をメガシンカ後の姿に切り替える。「メガストーン」は持ち物マスターデータに1種類だけ登録し、メガシンカ可能なすべてのポケモンに使用できる扱いとする。画像、名前、タイプ、種族値、特性などのフォーム依存情報はメガシンカ後のデータを表示し、能力値計算にもメガシンカ後の種族値を使う。特性の選択肢も表示中のフォームに合わせて切り替え、選択中の特性が切替後のフォームにない場合は選択を解除する。「メガストーン」以外に持ち物を変更した場合は、通常の姿と情報に戻す。登録データには通常のポケモンIDと持ち物IDを保存し、表示する姿はその組み合わせから判定する。

### 2.3 能力ポイントと実数値

- 能力ごとに種族値、能力ポイント入力欄、計算後の実数値を表示する。種族値と実数値は読み取り専用とする。
- 能力ポイントは各ステータス `0〜32` の整数で設定し、全ステータスの合計上限は `66` とする。合計値と残りポイントを表示する。
- 数値入力のほか、スライダーまたは「0」「32」ボタンで値を設定できるようにする。
- 各ステータスの上限または合計上限を超える入力は受け付けず、該当欄の近くに案内する。
- 新規登録フォームでポケモンを選択した直後は能力ポイントをすべて `0` とし、性格補正を反映した実数値を表示する。登録済みデータの呼び出し時は、保存されている能力ポイントと性格を使って実数値を表示する。
- 能力ポイントまたは性格が変更されたとき、実数値を即時に再計算する。性格補正は上昇・下降を文字や記号でも識別できるようにする。

#### 実数値の計算式

本仕様書ではレベル50、個体値相当の値を最大（31）に固定する。計算途中の小数点以下はすべて切り捨て、能力ポイントは以下の式で実数値に反映する。

- HP：`種族値 + 能力ポイント + 75`
  - 内部計算式：`floor((種族値 × 2 + 31 + 能力ポイント × 2) × 50 / 100) + 60`
  - 展開すると種族値と能力ポイントは整数のため、`floor(種族値 + 能力ポイント + 15.5) + 60` は `種族値 + 能力ポイント + 75` となる。
- HP以外：`floor((種族値 + 能力ポイント + 20) × 能力補正)`
  - 内部計算式：`floor((floor((種族値 × 2 + 31 + 能力ポイント × 2) × 50 / 100) + 5) × 能力補正)`
  - 内側の切り捨て後は必ず `種族値 + 能力ポイント + 15` となり、さらに `5` を加える。
- 能力補正は上昇 `1.1`、補正なし `1.0`、下降 `0.9` とする。補正を掛けた後も小数点以下を切り捨てる。
- ヌケニンのHP実数値は `1` 固定とする。

### 2.4 技構成

- 技を最大4つまで設定する。
- 選択肢は選択中のポケモンが覚える技に限定する。
- 同じ技を複数の枠に設定できないようにする。
- 技を選ぶと、タイプ、分類（物理・特殊・変化）、威力、命中を併記する。

### 2.5 ダメージ計算メモと備考

- **ダメージ計算メモ**：複数件を一覧表示し、手動で追加・削除できるようにする。将来、ダメージ計算画面から結果を受け渡せるデータ構造にする。
- **備考**：立ち回り、調整意図、パーティ内の役割などを記録する複数行入力欄を設ける。

### 2.6 保存・削除

- 画面固有の操作ボタンは共通フッターの操作領域に配置する。画面切り替え時に他画面の操作を表示しない。
- **保存**
  - ポケモン未選択、または入力値が仕様を満たさない場合は保存せず、該当項目の近くに理由を表示する。
  - 新規登録時は一意なIDを発行する。既存データの編集時はIDを維持して該当データを更新する。
  - 保存成功後は成功したことを通知し、保存したデータを引き続き編集できる状態にする。
- **削除**
  - 既存データの編集時のみ有効にする。
  - 確認ダイアログで削除を確認した後、該当データを削除してフォームを初期状態に戻す。
- `localStorage` の読み書きに失敗した場合は、成功したように扱わず、ユーザーにエラーを通知する。保存データの読み込みに失敗した場合も、空の登録一覧として扱ったり、既存データを上書きしたりしない。

## 3. データと保存方法

### 3.1 マスターデータ

- ポケモン、技、持ち物、性格のマスターデータは `data/` 内のJSONファイルに分けて管理する。
- 読み込みには相対パスを使い、GitHub Pagesのサブディレクトリでも動作するようにする。データが読み込めない場合は画面上にエラーを表示し、空のデータとして続行しない。
- マスターデータは必要なものを手動で追加・更新し、`data/` 内のJSONファイルで管理する。外部APIなどによる自動取得・更新は行わない。データ追加・変更時は既存の項目形式とIDを維持し、ポケモン・特性・技・持ち物・性格間の参照整合性を確認する。
- 「メガストーン」は `data/items.json` に共通の持ち物として1件だけ登録する。ポケモンごとのメガシンカ後フォーム情報は `data/pokemons.json` に保持し、個別のメガストーンIDは持たせない。

各ファイルはJSON配列とし、サンプルデータで使用しているキー名・構造を基準にする。

| ファイル | 項目と形式 |
| --- | --- |
| `data/pokemons.json` | `id`（図鑑番号）、`name`、`image`、`types`（タイプ名の配列）、`baseStats`（`hp`・`atk`・`def`・`spa`・`spd`・`spe`）、`abilities`（`id`・`name`の配列）、`learnset`（技IDの配列）、`megaForm`（メガシンカ後の情報一式、該当しない場合は`null`）。メガフォームにも`name`・`image`・`types`・`baseStats`・`abilities`を持たせる。 |
| `data/moves.json` | `id`、`name`、`type`、`category`、`power`、`accuracy`。変化技など該当しない数値は`null`とする。 |
| `data/items.json` | `id`、`name`。「メガストーン」はこの配列に1件だけ登録する。 |
| `data/natures.json` | `id`、`name`、`up`、`down`。補正なしの「まじめ」は`up`と`down`を`null`とする。 |

特性は独立したファイルに分けず、ポケモンまたはメガフォームの`abilities`に定義する。画像などのリソース参照は相対パスにする。データ間の関連付けには表示名ではなくIDを使い、タイプ名など選択肢そのものを表す値はサンプルの形式に合わせる。

### 3.2 登録データ

- `localStorage` の保存キーはツール名を表す `pokemon_tools_registered_list` とする。
- キーの値はJSON文字列化した登録データ配列とする。
- ポケモン、特性、性格、持ち物、技はIDで保持し、画面表示時にマスターデータから名前などを解決する。
- `damageCalcs` は当面、表示用テキストを保持する。ダメージ計算画面との連携を実装する際は、計算条件や結果を識別できる構造化データに移行する。

```json
[
  {
    "id": "一意な登録ID",
    "pokemonId": 445,
    "abilityId": "rough-skin",
    "natureId": "jolly",
    "itemId": "focus-sash",
    "abilityPoints": {
      "hp": 2,
      "atk": 32,
      "def": 0,
      "spa": 0,
      "spd": 0,
      "spe": 32
    },
    "moveIds": ["earthquake", "outrage", "swords-dance", "iron-head"],
    "damageCalcs": [
      "HP能力ポイント32のサーフゴーに対する「じしん」のダメージ計算結果"
    ],
    "notes": "初手に出して削りを行う役割。",
    "updatedAt": "2026-10-23T22:30:00.000Z"
  }
]
```

## 4. 入力検証と状態

- ポケモン未選択、無効な特性・性格・持ち物、能力ポイントの個別上限超過、能力ポイント合計超過、整数でない能力ポイント、4枠を超える技、覚えない技、技の重複を保存前に検証する。
- エラーは対象項目の近くに説明を表示し、色だけでエラーを示さない。
- 登録一覧が空、検索結果が空、マスターデータの読み込み失敗、保存失敗をそれぞれ区別して案内する。
- 検索から呼び出した既存データと新規作成状態を区別し、削除可否と保存時の追加・更新動作を一貫させる。

## 5. 実装・画面上の共通ルール

- 画面は既存の `index.html`、`style.css`、`script.js` の構成とURLハッシュによる画面切り替えに統合する。
- 新しい入力欄には可視ラベルを付け、プレースホルダーだけをラベル代わりにしない。
- 色、余白、カード、入力欄、フォーカス表示、ダークモード、レスポンシブ対応は[スタイルガイド](./00-style-guide.md)に従う。
- 操作はキーボードでも利用できるようにし、フォーカス表示を維持する。動きを追加する場合は、スタイルガイドに記載された動きを抑制する設定を尊重する。
