# ポケモンツール スタイルガイド

このガイドは、現在のホーム画面と共通レイアウトの実装（`index.html`・`style.css`）を基準にしています。新しい画面や機能を追加するときも、共通の色・余白・角丸・操作状態を引き継ぎ、アプリ全体に統一感を持たせてください。

## 1. デザインの基本方針

- 明るく見やすい、清潔感のある画面にする。
- 薄いグレーのページ背景と白い面を基本にし、赤を操作や強調のアクセントとして使う。
- 情報はカードやまとまりごとに整理する。装飾よりも、機能名・入力内容・結果の読みやすさを優先する。
- PCとスマートフォンの両方で使いやすくする。狭い画面では横幅を無理に詰めず、縦方向に並べる。
- ライト／ダークのどちらでも同じ情報設計と操作性を保つ。

## 2. カラー

色はCSSカスタムプロパティを通じて指定してください。テーマ固有の色をコンポーネントに直接埋め込まず、ライト／ダーク両方で自然に切り替わるようにします。

| 用途 | カスタムプロパティ | ライトテーマ | ダークテーマ |
| --- | --- | --- | --- |
| ページ背景 | `--page-bg` | `#f4f5f7` | `#202329` |
| カード・共通エリアの面 | `--surface` | `#ffffff` | `#2b3038` |
| 基本文字 | `--text` | `#252a34` | `#f3f4f6` |
| 補助文字 | `--muted` | `#667085` | `#b0b7c3` |
| 境界線 | `--border` | `#e4e7ec` | `#414752` |
| アクセント | `--accent` | `#e63d4f` | `#ff6675` |
| 強調時のアクセント | `--accent-dark` | `#c92e40` | `#ff8290` |
| アクセント上の文字 | `--accent-contrast` | `#ffffff` | `#252a34` |
| アクセントの淡い面 | `--soft-accent` | `#fff0f1` | `#493037` |
| 標準の影 | `--shadow` | `0 0.75rem 2rem rgb(31 41 55 / 7%)` | `0 0.75rem 2rem rgb(0 0 0 / 20%)` |
| ホバー時の影 | `--shadow-hover` | `0 1rem 2.25rem rgb(31 41 55 / 12%)` | `0 1rem 2.25rem rgb(0 0 0 / 32%)` |

- 通常の本文は `--text`、説明・補足・非選択状態は `--muted` を使います。
- 赤は主要な操作、選択中のナビゲーション、アイコンなど、意味のある強調に使います。広い背景を赤で塗りつぶす用途には使いません。
- 薄い境界線と影を併用し、面の境目が分かるようにします。過度に強い影や多色使いは避けます。
- 新しい色が本当に必要な場合は、用途を明確にして `:root` に変数として追加し、ダークテーマの値も定義します。

## 3. 文字と情報の階層

- 基本フォントは `"Segoe UI", "Noto Sans JP", sans-serif`。追加のWebフォントや外部ライブラリは使いません。
- ページの主見出しは `h1` を使い、現在は `clamp(1.8rem, 5vw, 2.65rem)` と `line-height: 1.3` で画面幅に応じて調整しています。
- 小さな英字ラベル（`.eyebrow`）はアクセント色、`0.75rem`、太字、文字間隔 `0.12em` を基本とします。ラベルは見出しの補助として使い、見出しの代わりにしません。
- カード見出しは `1.15rem`・太字、本文や説明は `0.9rem` 前後・補助文字色を基本にします。
- 本文は読みやすい行間を確保します。説明文では現在の `line-height: 1.7`〜`1.8` を目安にしてください。
- 文字サイズは必要に応じて `rem` と `clamp()` を使い、画面サイズに応じた読みやすさを保ちます。

## 4. レイアウトと余白

- 共通のページ構造は、上部のヘッダー、中央のメイン領域、下部のフッターです。本文が短い画面でもフッターが下に配置されるよう、`body` の縦Flexレイアウトを維持します。
- メイン領域は最大幅 `76rem`、左右の余白は `clamp()` で画面幅に応じて調整します。画面全体にコンテンツを広げすぎないでください。
- ヘッダーは `position: sticky` で上部に固定し、フッターとともに `--surface` の背景と `--border` の境界線を使います。
- 関連する要素はまとまりとして配置し、セクション間には十分な余白を設けます。既存の `0.5rem`、`0.75rem`、`1rem`、`1.25rem`、`1.75rem` などの間隔を基本に、近い値を再利用してください。
- カード一覧にはCSS Gridを使います。ホーム画面は広い画面で3列、狭い画面で1列です。新しい一覧も項目の読みやすさを優先し、無理な多列表示を避けます。
- 配置にはFlexboxまたはGridを使い、固定幅や位置指定への過度な依存を避けます。

## 5. 面・カード・角丸・影

- カードや入力領域などの面は `--surface`、境界線は `--border` を基本にします。
- ホーム画面の機能カードは、`1rem` の角丸、`1px` の境界線、`--shadow` を使います。アイコンの背景枠も角丸を使い、カードとのまとまりを作ります。
- 機能画面のまとまりを示すカードは、ホーム画面と同程度の角丸・境界線・影を使います。画面ごとに異なるカード様式を増やさないでください。
- 複数の階層を示す必要がある場合は、影を強くするより、余白・見出し・境界線で整理します。

## 6. 操作部品と状態

- クリックできる領域は、リンクにはリンク、処理を実行するボタンにはボタンを使います。カード全体を遷移させる場合は、現在の機能カードと同じくカード全体をリンクにします。
- 主操作はアクセント色の背景、`--accent-contrast` の文字、太字を基本とします。現在のホームボタンを基準に、適切な最小高さと左右の余白を確保してください。
- 補助操作は、テーマ切替ボタンのように背景を透明にし、補助文字色で表示できます。主操作と補助操作の見分けを保ってください。
- 選択中のナビゲーションはアクセント色で示します。操作状態は色だけに頼らず、必要に応じて `aria-current` や `aria-pressed` など適切な属性も更新します。
- カードのホバー時は、わずかな浮き上がり（現在は `translateY(-5px)`）、境界線のアクセント色化、影の変化を使います。矢印などの補助表現も小さく動かす程度にします。
- ボタンやリンクのホバーでは色または位置を控えめに変化させます。ホバーだけで重要な情報を伝えないでください。
- キーボード操作時には `:focus-visible` のアウトラインを表示します。新しい操作部品でも見えるフォーカス表示を消さないでください。
- 動きを追加するときは短く控えめにし、`prefers-reduced-motion: reduce` の設定を尊重します。

## 7. 入力フォーム・結果表示を追加するとき

現在の画面にはフォームや計算結果の表示スタイルはまだありません。追加時は次を共通ルールとし、実装後にこのガイドの具体例を更新してください。

- 入力欄は背景に `--surface`、文字に `--text`、境界線に `--border` を使います。入力値、ラベル、補足説明、エラーを明確に区別します。
- すべての入力欄に、内容が分かる可視ラベルを付けます。プレースホルダーだけをラベル代わりにしません。
- 入力欄・ボタンはタップしやすい高さと間隔を確保し、キーボードフォーカスを明瞭に表示します。
- 入力エラーは該当項目の近くに説明を表示し、色だけで状態を伝えません。
- 計算結果や保存済みデータは、見出しと余白でまとまりを作り、重要な値と補足情報の視覚的な優先順位を分けます。

## 8. レスポンシブ対応

現在のCSSでは以下のブレークポイントを使っています。

- `760px` 以下：ヘッダーを折り返し、ナビゲーションを横幅いっぱいに配置。ホームのカード一覧は1列にします。
- `420px` 以下：ブランド名とナビゲーションの文字サイズを小さくし、説明文中のデスクトップ向け改行を解除します。

新しい画面でも、狭い画面で横スクロールや文字の切れが発生しないことを確認してください。横に並べた入力欄や表は、必要に応じて縦積みや横スクロール可能な領域に切り替えます。ヘッダーのナビゲーションは既存どおり横スクロールを許容します。

## 9. アイコンと装飾

- アイコンは既存のようなシンプルなインラインSVGを基本にし、線幅や角の表現を画面内で揃えます。
- 装飾目的のアイコンは支援技術から隠し（`aria-hidden="true"`）、操作の意味はテキストでも分かるようにします。
- アイコンの色は `currentColor` を使い、テーマや状態に合わせて変わるようにします。アクセント色の淡い面には `--soft-accent` を使います。
- 絵文字や異なるアイコンセットを混在させず、装飾は機能や状態の理解を助ける範囲にとどめます。

## 10. 実装時の確認項目

- 色は既存のカスタムプロパティを使い、ライト／ダーク両方で読める。
- 見出し・本文・補助情報の階層が明確で、既存と近い文字サイズ・行間になっている。
- 余白・角丸・境界線・影が既存のカードや共通エリアと調和している。
- PCと幅 `760px` 以下、`420px` 以下でレイアウトが崩れない。
- キーボードで操作でき、フォーカスが見え、動きを減らす設定が尊重されている。
- 状態やエラーが色だけに依存せず、文字やアクセシビリティ属性でも伝わる。
